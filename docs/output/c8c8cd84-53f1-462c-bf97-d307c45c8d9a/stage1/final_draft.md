## 二、引言

### 2.1 编写目的

本文档将业务侧已确认的《存量用户组迁移方案（IAM 身份中心）》转化为可开发、可测试、可验收的需求规格说明，明确该迁移能力的功能边界、接口契约、数据口径、非功能指标与验收标准，作为研发实现、测试用例设计与上线验收的共同依据。

本文档的读者包括：产品负责人、后端研发、测试工程师、云平台运维、安全与合规评审人员。

### 2.2 项目背景

当前云上存在一批存量用户，其权限通过旧用户组继承获得，包含业务上已不再需要的权限（例如对象存储的 ListBucket 等列举类权限）。为落实权限最小化原则、收敛存量授权面，需要将这批存量用户从旧用户组迁移至目标新用户组。

迁移在华为云 IAM 身份中心（Identity Center）层面完成，本质是调整"用户—用户组"成员关系（Membership）：解除用户与旧用户组的绑定，并建立用户与目标用户组的绑定。业务侧已完成接口可行性验证，确认仅需 4 个开放接口、拆分为 2 个相互独立的功能即可覆盖迁移诉求。

### 2.3 名词与缩略语

| 术语 | 说明 |
|------|------|
| IAM 身份中心 | 华为云统一身份管理服务，提供用户、用户组、成员关系的集中管理能力 |
| 身份源（Identity Store） | 身份中心的用户与用户组数据容器，由 `identity_store_id` 唯一标识 |
| 用户组（Group） | 权限的集合载体，用户加入用户组后即拥有该组的全部权限 |
| 成员关系（Membership） | "用户—用户组"的绑定记录，由 `membership_id` 唯一标识 |
| 旧用户组 | 存量用户当前所属的用户组，待解除绑定 |
| 目标新用户组 | 存量用户迁移后应归属的用户组 |
| 会话令牌 | 使用临时安全凭据调用接口时需在请求头携带的 `X-Security-Token` |
| 幂等 | 同一操作重复执行不产生额外副作用（重复解绑、重复绑定均视为成功） |
| 权限空档 | 用户已退出旧组但尚未加入新组的中间状态，此时用户权限为两者的差集 |

## 三、总体描述

### 3.1 产品定位与范围

本需求交付一项**存量用户组迁移能力**（形态为运维侧迁移任务／脚本工具，非面向最终用户的 Web 界面），供运维人员按批次将存量用户从旧用户组迁移至目标新用户组。

**本期包含：**

1. 迁移配置的加载与校验；
2. 功能一：用户退出旧组（查询用户所属用户组 → 解绑成员关系）；
3. 功能二：用户加入新组（查询目标用户组 → 绑定成员关系）；
4. 批量迁移的顺序编排、执行记录、结果汇总与断点续跑。

**本期不包含（明确范围外）：**

| 编号 | 范围外事项 | 说明 |
|------|-----------|------|
| OUT-01 | 成员关系校验与抽查 | 两个功能均以写接口成功返回为完成标志，不追加核对类调用 |
| OUT-02 | 目标新用户组的创建与权限策略配置 | 作为迁移前置条件，由权限管理流程预先完成 |
| OUT-03 | 用户身份源的创建与用户开户 | 存量用户已存在，本期不涉及 |
| OUT-04 | 图形化操作界面 | 如需可视化编排界面，另行立项评估 |
| OUT-05 | 迁移结果的自动回滚 | 本期仅提供失败重试与人工回退说明，不实现自动回滚 |

> 说明：OUT-01 意味着迁移结果缺乏自动化校验手段，其带来的可观测性缺口已在第十二章风险项 RK-04 中登记，并以执行记录与人工抽检作为补偿措施。

### 3.2 用户角色与特征

| 角色 | 职责 | 特征与关注点 |
|------|------|--------------|
| 平台运维工程师（主用户） | 执行迁移任务、处理失败项、输出结果报告 | 熟悉云 API 与命令行，关注执行可控性、可重试性与结果可追溯 |
| 安全合规负责人 | 审批迁移方案、确认权限收敛结果 | 关注最小权限、操作留痕、审计可回溯 |
| 业务/应用负责人 | 知会迁移窗口与影响范围 | 关注迁移期间业务连续性，避免权限空档导致业务中断 |

### 3.3 运行环境

| 项目 | 要求 |
|------|------|
| 调用主体 | 组织管理账号，或已配置为服务委托管理员的成员账号（接口文档明确要求） |
| 认证方式 | 永久 AK/SK，或临时安全凭据（后者需额外在请求头携带 `X-Security-Token` 会话令牌） |
| 网络 | 运行环境需可访问 IAM 身份中心 OpenAPI 服务端点（具体 Region 与 Endpoint 待确认，见 TBD-02） |
| 运行时 | 支持 HTTPS 请求与 JSON 解析的脚本运行时（技术栈由研发确定） |
| 数据存放 | 迁移清单、执行记录与日志存放于运维侧受控目录，不入代码仓库 |

### 3.4 设计与实现约束

| 编号 | 约束 | 来源 |
|------|------|------|
| CST-01 | `identity_store_id` 以固定值保存在配置文件中，各接口路径参数直接引用，不逐次解析；接口文档标注该参数长度最小／最大均为 12 位 | REF-01 / REF-02 |
| CST-02 | 分页参数 `limit` 有效范围 1–100，缺省 100；必须以响应中的 `next_marker` 持续翻页直至返回 `null` | REF-02 |
| CST-03 | 解绑所需的 `membership_id` 只能从"列出用户加入的组"的查询结果中获取，不得自行拼装 | REF-01 |
| CST-04 | 绑定与解绑均以单个"用户—用户组"关系为操作粒度，不支持批量接口 | REF-02 |
| CST-05 | 绑定用户与用户组必须属于同一身份源 | REF-02 |
| CST-06 | 迁移流程止于写操作成功返回，不追加校验、抽查类接口（IsMemberInGroups、ListGroupMemberships、DescribeGroupMembership、DescribeGroups 等不进入本期范围） | REF-01 |
| CST-07 | 选组环节直接复用 `ListGroups` 响应返回的 `group_id`，无须调用查询用户组 ID 的辅助接口 | REF-01 |

### 3.5 假设与依赖

| 编号 | 类型 | 内容 | 影响 |
|------|------|------|------|
| ASM-01 | 假设 | 存量用户清单可由业务侧提供，字段为 `user_id`，规模在千级以内 | 影响性能指标与批次切分策略，规模待 TBD-01 确认 |
| ASM-02 | 假设 | 目标新用户组的 `display_name` 在身份源内唯一 | 若不唯一，按 FR-04 中止并要求人工指定 `group_id` |
| ASM-03 | 假设 | 旧用户组的 `group_id` 可提前获得并作为配置项或任务参数传入 | 本功能不通过 `ListGroups` 反查旧组 |
| ASM-04 | 假设 | 迁移在业务低峰窗口执行，可接受迁移期间极短的权限变更 | 影响编排顺序设计（先加后减） |
| DEP-01 | 依赖 | 目标新用户组已创建且权限策略已配置完成 | 未就绪则迁移结果不符合预期 |
| DEP-02 | 依赖 | 调用账号具备 4 个接口的最小权限 | 缺失则任务无法启动 |
| DEP-03 | 依赖 | IAM 身份中心服务可用，且接口限流阈值满足批量调用需求 | 影响并发度与耗时，限流阈值待 TBD-03 确认 |
| DEP-04 | 依赖 | 临时安全凭据在任务执行期内有效 | 凭据过期将导致批量失败 |

## 四、需求概述

### 4.1 功能清单

| 功能编号 | 功能名称 | 接口调用序列 | 作用 |
|----------|----------|--------------|------|
| F-01 | 迁移配置加载与校验 | 无（本地） | 校验身份源、组标识、认证信息与用户清单可用性 |
| F-02 | 用户退出旧组 | ListGroupMembershipsForMember → DeleteGroupMembership | 定位"用户—旧组"关联关系并解绑 |
| F-03 | 用户加入新组 | ListGroups → CreateGroupMembership | 选定目标用户组并将用户绑定至该组 |
| F-04 | 批量迁移编排 | 组合 F-02、F-03 | 按"先加入新组、再退出旧组"顺序逐用户执行 |
| F-05 | 执行记录与结果汇总 | 无（本地） | 逐用户留痕并输出汇总报告 |
| F-06 | 失败重试与断点续跑 | 组合 F-02、F-03 | 对可重试错误自动重试，支持中断后继续执行 |

### 4.2 关键业务规则

| 编号 | 规则 | 依据 |
|------|------|------|
| BR-01 | 批量迁移必须按"先加入新组、再退出旧组"的顺序执行，以保证用户权限只增不减，避免迁移过程中的权限空档 | REF-01 第四章 |
| BR-02 | 仅将用户加入新组不会自动剥离旧组权限；旧组权限在"退出旧组"成功后才失效 | REF-01 第四章 |
| BR-03 | 用户若不在旧组中，跳过解绑步骤，判定为"无需解绑"，不计为失败 | REF-01 第二章 |
| BR-04 | 两个功能相互独立，可分别执行、分别重试；任一功能单独失败不影响另一功能已产生的效果 | REF-01 第四章 |
| BR-05 | 单个用户迁移失败不阻断后续用户执行（fail-soft），但全局性错误（配置错误、目标组不存在、认证失败）必须立即中止整个任务 | 本文档设计决策，见 7.4 |

### 4.3 用户故事

| 编号 | 用户故事 | 验收关联 |
|------|----------|----------|
| US-01 | 作为平台运维工程师，我希望按用户清单批量完成组迁移，以便在不逐个手工操作的前提下收敛存量权限 | AC-01、AC-07 |
| US-02 | 作为平台运维工程师，我希望迁移过程中用户权限不出现空档，以便业务不因权限变更中断 | AC-03 |
| US-03 | 作为平台运维工程师，我希望对网络抖动等临时故障自动重试，并能从中断处继续执行，以便长任务不因单点失败而全量重跑 | AC-08 |
| US-04 | 作为安全合规负责人，我希望每个用户的迁移动作都有结构化留痕，以便事后审计与权限核对 | AC-09 |
| US-05 | 作为平台运维工程师，我希望在正式执行前预览将执行的变更清单，以便降低误操作风险 | AC-10 |

## 五、功能需求

### 5.1 FR-01 迁移配置加载与校验

**优先级：** 必须（Must）

**需求描述：** 任务启动时加载迁移配置并完成前置校验，任一项校验失败立即终止，且不得发起任何写接口调用。

**配置项：**

| 配置项 | 必填 | 说明 | 校验规则 |
|--------|------|------|----------|
| `identity_store_id` | 是 | 身份源 ID | 非空，长度等于 12 位 |
| `endpoint` / `region` | 是 | 身份中心服务端点 | 非空，可解析 |
| 认证凭据 | 是 | AK/SK 或临时凭据 | 非空；使用临时凭据时 `security_token` 必填 |
| `old_group_id` | 是 | 旧用户组 ID | 非空 |
| `target_group_display_name` | 是 | 目标新组显示名 | 非空 |
| 用户清单 | 是 | 待迁移 `user_id` 列表 | 非空、无重复、格式合法 |
| `concurrency` | 否 | 并发度 | 默认 1，取值范围 1–3（待 TBD-03 确认上限） |
| `dry_run` | 否 | 是否只预演不写入 | 默认 false |

**验收标准：**

- Given 配置文件中 `identity_store_id` 缺失或长度不为 12 位，When 启动任务，Then 任务在配置校验阶段终止，输出明确错误提示，且不产生任何接口调用。
- Given 用户清单为空或含重复 `user_id`，When 启动任务，Then 任务终止并提示具体行号或重复项。
- Given 使用临时安全凭据但未提供会话令牌，When 启动任务，Then 任务终止并提示补充 `X-Security-Token`。
- Given 全部配置校验通过，When 启动任务，Then 进入选组阶段（FR-04 步骤一），并记录任务开始时间与配置摘要（凭据信息脱敏）。

### 5.2 FR-02 查询用户已加入的用户组

**优先级：** 必须（Must）

**需求描述：** 调用 `ListGroupMembershipsForMember` 拉取指定用户加入的全部用户组，必要时分页取全，并在结果中定位旧用户组对应的成员关系。

**处理规则：**

1. Query 参数传 `user_id`（必选）、`limit`（取值 100）、`marker`（首次为空）；
2. 判断响应 `page_info.next_marker`，非 `null` 时以其继续请求，直至返回 `null`，保证结果取全；
3. 在汇总后的 `group_memberships` 列表中，按 `group_id` 等于配置的 `old_group_id` 精确匹配，取出该记录的 `membership_id`；
4. 匹配到唯一记录 → 进入解绑（FR-03）；
5. 未匹配到任何记录 → 判定该用户不在旧组，状态置 `SKIPPED_NOT_IN_OLD_GROUP`，不调用解绑接口；
6. 匹配到多条记录（异常情况）→ 取第一条执行，并记录告警日志，状态附注 `WARN_MULTI_MATCH`。

**验收标准：**

- Given 用户加入的组超过 100 个，When 查询其所属用户组，Then 系统按 `next_marker` 翻页直至取全，最终匹配结果不受分页截断影响。
- Given 用户所属组中包含旧用户组，When 完成匹配，Then 输出该用户对应的 `membership_id`。
- Given 用户不属于旧用户组，When 完成匹配，Then 不调用解绑接口，该用户状态为"跳过：不在旧组"，且不计入失败数。
- Given 查询接口返回可重试错误，When 达到重试次数上限仍失败，Then 该用户状态置为失败，记录 `error_code`、`error_msg` 与 `request_id`。

### 5.3 FR-03 用户退出旧组（功能一）

**优先级：** 必须（Must）

**需求描述：** 调用 `DeleteGroupMembership`，以 FR-02 取得的 `membership_id` 解除用户与旧用户组的绑定。

**处理规则：**

1. 路径参数传 `identity_store_id` 与 `membership_id`，无请求体；
2. 接口成功时无响应体，以 HTTP 2xx 成功返回作为迁移完成标志；
3. 响应 404 且语义为成员关系不存在时，视为目标已达成，状态置 `ALREADY_REMOVED`（幂等成功），不计为失败；
4. 其他错误按第八章异常处理策略处理。

**验收标准：**

- Given 已取得有效 `membership_id`，When 调用解绑接口，Then 返回成功，该用户在旧组中的成员关系被移除，状态记为成功。
- Given 该成员关系已被移除（重复执行），When 再次调用解绑接口，Then 状态记为"已移除"，任务整体仍可正常结束。
- Given 解绑成功但后续无任何校验调用，When 任务结束，Then 执行记录中包含解绑时间、`membership_id` 与请求 `request_id`，供事后核对。

### 5.4 FR-04 用户加入新组（功能二）

**优先级：** 必须（Must）

**需求描述：** 先通过 `ListGroups` 选定目标用户组，再通过 `CreateGroupMembership` 将用户绑定至该组。

**步骤一：选组（每批次执行一次）**

1. 调用 `ListGroups`，Query 参数可传 `display_name` 做模糊查询缩小范围，`limit` 取 100，按 `next_marker` 翻页取全；
2. 在返回的 `groups[]` 中按 `display_name` 精确匹配配置的目标组名称，取出其 `group_id`；
3. 匹配唯一 → 缓存 `group_id` 供本批次全部用户复用，不逐用户重复调用；
4. 匹配为 0 条 → 全局致命错误 `FATAL_TARGET_GROUP_NOT_FOUND`，整个任务终止（后续绑定必然失败）；
5. 匹配多条同名组 → 全局致命错误 `FATAL_TARGET_GROUP_AMBIGUOUS`，任务终止并提示人工指定 `group_id`。

**步骤二：绑定（每用户一次）**

1. 请求体传 `group_id`、`member_id.user_id`、`identity_store_id`；
2. 响应返回 `membership_id` 即视为加入成功；
3. 响应 409 且语义为关系已存在时，视为幂等成功，状态置 `ALREADY_JOINED`。

**验收标准：**

- Given 目标组 `display_name` 在身份源内唯一存在，When 执行选组，Then 取得唯一 `group_id` 并在本批次内复用，`ListGroups` 调用次数不随用户数线性增长。
- Given 目标组名称模糊匹配到多个候选但无精确匹配，When 执行选组，Then 任务终止并提示可用候选列表。
- Given 目标组同名存在多个，When 执行选组，Then 任务终止并提示人工指定 `group_id`，不执行任何绑定。
- Given 已取得 `group_id`，When 对用户执行绑定，Then 返回 `membership_id`，用户获得目标组的全部权限。
- Given 用户已在目标组中，When 重复执行绑定，Then 状态记为"已加入"，不计为失败。

### 5.5 FR-05 批量迁移编排

**优先级：** 必须（Must）

**需求描述：** 按用户清单逐条执行迁移，严格遵循"先加入新组、再退出旧组"的顺序。

**编排规则：**

1. 任务级前置：完成 FR-01 校验与 FR-04 选组，取得 `group_id`；
2. 单用户执行顺序：绑定新组（FR-04 步骤二）→ 解绑旧组（FR-02 + FR-03）；
3. 若绑定失败，则该用户不执行解绑（避免产生权限空档），状态置失败并进入重试；
4. 若绑定成功而解绑失败，状态置"部分成功"，用户同时拥有新旧两组权限，记入待处理清单；
5. 单个用户失败不中断批次，继续下一用户；
6. 命中全局致命错误时立即中止，保留已完成用户的执行记录，支持断点续跑。

**验收标准：**

- Given 批次含 N 个用户，When 执行迁移，Then 每个用户均先完成绑定再执行解绑，执行记录中的时间戳顺序可验证该顺序。
- Given 某用户绑定失败，When 处理该用户，Then 不调用解绑接口，该用户权限保持不变。
- Given 某用户绑定成功、解绑失败，When 汇总结果，Then 该用户计入"部分成功"，并在报告中单独列出。
- Given 批次中第 K 个用户失败，When 继续执行，Then 第 K+1 个用户正常执行，任务不中断。

### 5.6 FR-06 执行记录与结果汇总

**优先级：** 必须（Must）

**需求描述：** 为每个用户生成一条结构化执行记录，并在任务结束后输出汇总报告。

**汇总指标：**

| 指标 | 口径 |
|------|------|
| 总数 | 本批次输入 `user_id` 去重后的数量 |
| 成功数 | 绑定成功且解绑成功（含"已加入""已移除"幂等成功）的用户数 |
| 跳过数 | 用户不在旧组（`SKIPPED_NOT_IN_OLD_GROUP`）且已成功加入新组的用户数 |
| 部分成功数 | 绑定成功但解绑失败的用户数 |
| 失败数 | 绑定失败的用户数（含重试后仍失败） |
| 成功率 | 成功数 ÷ 总数 × 100%，保留两位小数 |
| 总耗时 | 任务结束时间减任务开始时间，单位秒 |

**验收标准：**

- Given 任务执行完毕，When 输出汇总，Then 成功数 + 跳过数 + 部分成功数 + 失败数等于总数。
- Given 任务执行完毕，When 输出记录文件，Then 每条记录包含 `user_id`（脱敏）、状态、开始与结束时间、`request_id`、重试次数、错误码（如有）。
- Given 任务因致命错误中止，When 输出汇总，Then 报告标注任务状态为"中止"，并列出已完成与未执行的用户数量。

### 5.7 FR-07 失败重试与断点续跑

**优先级：** 必须（Must）

**需求描述：** 对可重试错误按策略自动重试；任务中断后支持从断点继续，已成功用户不重复处理。

**处理规则：**

1. 可重试：网络超时、连接失败、HTTP 5xx、HTTP 429（限流）；
2. 不可重试：4xx 中的参数错误、权限不足、资源不存在（404 在解绑场景按幂等处理）等业务语义错误；
3. 重试次数上限 3 次，间隔采用指数退避（1s、2s、4s，可配置）；
4. 重试仍失败 → 状态置失败，记录最后一次错误信息与 `request_id`；
5. 断点续跑：以 `user_id` 为键，续跑时读取既有执行记录，状态为成功或已跳过的用户直接略过；
6. 续跑不改变已有记录的原始时间戳，追加续跑批次标识。

**验收标准：**

- Given 接口返回 500，When 执行调用，Then 系统按 1s/2s/4s 退避重试，最多 3 次，并在记录中体现重试次数。
- Given 接口返回 403 权限不足，When 执行调用，Then 不重试，直接置失败并终止整个任务（权限问题对全批次同质）。
- Given 任务在第 50 个用户处中断，When 以同一清单续跑，Then 前 49 个已成功用户被跳过，从第 50 个用户继续。

### 5.8 FR-08 迁移预演（Dry Run）

**优先级：** 应该（Should）

**需求描述：** 支持预演模式，仅执行配置校验、选组与"查询用户所属组"的只读调用，输出将执行的变更清单，不调用任何写接口。

**验收标准：**

- Given `dry_run` 为 true，When 执行任务，Then 仅产生读接口调用，输出每个用户的预期动作（加入目标组 / 无需解绑 / 需人工确认），不修改任何成员关系。
- Given 预演输出，When 运维确认无误，Then 可切换为正式执行，配置无需重复录入。

## 八、异常处理需求

### 8.1 异常分类与处理策略

| 编号 | 异常场景 | 判定依据 | 处理策略 | 是否重试 | 用户状态 |
|------|----------|----------|----------|----------|----------|
| EX-01 | 网络超时／连接失败 | 请求异常无响应 | 指数退避重试 | 是（≤3 次） | `RETRYING` → `FAILED` |
| EX-02 | 服务端错误 | HTTP 5xx | 指数退避重试 | 是（≤3 次） | 同上 |
| EX-03 | 触发限流 | HTTP 429 | 加大退避间隔后重试 | 是（≤3 次） | 同上 |
| EX-04 | 认证失败／凭据过期 | HTTP 401 | 立即中止整个任务 | 否 | 任务 `ABORTED` |
| EX-05 | 权限不足 | HTTP 403 | 立即中止整个任务（权限问题对全批次同质） | 否 | 任务 `ABORTED` |
| EX-06 | 成员关系不存在（解绑） | HTTP 404 | 视为已达成目标，记幂等成功 | 否 | `ALREADY_REMOVED` |
| EX-07 | 成员关系已存在（绑定） | HTTP 409 | 视为已达成目标，记幂等成功 | 否 | `ALREADY_JOINED` |
| EX-08 | 请求参数非法 | HTTP 400 | 不重试，记录参数快照，跳过该用户 | 否 | `FAILED` |
| EX-09 | 目标组不存在 | 选组结果为空 | 全局致命，任务中止 | 否 | 任务 `ABORTED` |
| EX-10 | 目标组同名多条 | 选组结果多条精确匹配 | 全局致命，任务中止并提示人工指定 | 否 | 任务 `ABORTED` |
| EX-11 | 分页翻页中断 | 翻页请求失败 | 对当前页重试，重试耗尽则该用户失败 | 是 | `FAILED` |
| EX-12 | 用户不在旧组 | 查询结果无匹配 | 跳过解绑，不视为异常 | 否 | `SKIPPED_NOT_IN_OLD_GROUP` |
| EX-13 | 用户与组不在同一身份源 | HTTP 400 且语义指明身份源不匹配 | 不重试，记录并要求人工核对 | 否 | `FAILED` |
| EX-14 | 清单存在无效 `user_id` | 格式校验不通过 | 记录并跳过，任务继续 | 否 | `SKIPPED` |

> 错误码取值以 REF-02《IAM 身份中心 API 参考》为准，本文档只定义处理策略与状态映射，不重复罗列全部错误码。

### 8.2 边界条件

| 编号 | 边界场景 | 要求 |
|------|----------|------|
| BD-01 | 用户所属组数量超过 100 | 必须翻页取全，不得遗漏 |
| BD-02 | 目标组成员已达上限 | 绑定失败，记录错误并提示人工处理 |
| BD-03 | 清单规模极大（超过单批次上限） | 支持按批次切分，批次间串行执行，记录批次标识 |
| BD-04 | 任务执行中进程被中断 | 已落盘记录不丢失，支持续跑 |

## 十、业务流程设计

### 10.1 批量迁移主流程

1. **开始** → 加载配置 → FR-01 校验；
2. 校验失败 → 任务 `ABORTED`，输出错误明细，**结束**；
3. 校验通过 → 任务 `CONFIG_VALIDATED` → 执行 FR-04 步骤一（选组）；
4. 选组失败（0 条或多条同名）→ 任务 `ABORTED`，输出候选列表，**结束**；
5. 选组成功 → 缓存 `group_id`，任务 `GROUP_RESOLVED` → 遍历用户清单（去重后）；
6. 对每个用户：
   - a. 绑定新组（FR-04 步骤二）→ 失败则记录 `FAILED`，**跳过解绑**，进入下一个用户；
   - b. 绑定成功 → 查询用户所属组（FR-02）→ 按 `next_marker` 翻页取全；
   - c. 匹配到旧组 → 解绑（FR-03）→ 成功记 `SUCCESS`，失败记 `PARTIAL`；
   - d. 未匹配到旧组 → 记 `SKIPPED`，不调用解绑；
7. 全部用户处理完毕 → 输出汇总报告 → 任务 `COMPLETED` 或 `PARTIAL_COMPLETED`，**结束**；
8. 过程中命中致命错误 → 保存已完成记录 → 任务 `ABORTED`，**结束**（支持续跑）。

### 10.2 编排顺序说明

业务侧已明确：仅将用户加入新组不会自动剥离旧组权限，旧组权限在"退出旧组"完成后才失效。因此按"先加入新组、再退出旧组"执行，用户在整个过程中同时拥有新旧两组的权限并集，不存在权限空档。若顺序颠倒，用户将在一段时间内不含任何一组的权限，可能导致业务中断。

### 10.3 时序说明（单用户）

| 步骤 | 动作 | 依赖 | 失败影响 |
|------|------|------|----------|
| 1 | 调用 API-04 绑定新组 | 已取得 `group_id` | 用户权限不变，状态 `FAILED` |
| 2 | 调用 API-01 查询所属组 | 绑定成功 | 用户已获新组权限，旧组未剥离，状态 `PARTIAL` |
| 3 | 调用 API-02 解绑旧组 | 已取得 `membership_id` | 同上，状态 `PARTIAL` |

## 十一、验收标准

| 编号 | 验收场景 | 前置条件 | 预期结果 |
|------|----------|----------|----------|
| AC-01 | 完整迁移正常用户 | 用户属于旧组，目标组存在且唯一 | 绑定成功、解绑成功，最终只属于新组，状态 `SUCCESS` |
| AC-02 | 用户不在旧组 | 用户不属于旧组 | 绑定成功，跳过解绑，状态 `SKIPPED`，不计失败 |
| AC-03 | 权限空档验证 | 迁移过程中持续观测 | 任一时点用户至少拥有新组权限，未出现两组权限均缺失 |
| AC-04 | 目标组不存在 | 配置的目标组名称无匹配 | 任务 `ABORTED`，无任何写操作发生 |
| AC-05 | 目标组同名多条 | 存在多个同名组 | 任务 `ABORTED`，提示人工指定 `group_id` |
| AC-06 | 配置非法 | `identity_store_id` 长度不为 12 | 任务终止，无接口调用 |
| AC-07 | 批量执行 | 清单含 100 个混合状态用户 | 各状态计数之和等于总数，报告可核对 |
| AC-08 | 断点续跑 | 任务中途中断后以同一清单重跑 | 已成功用户被跳过，未完成用户继续执行 |
| AC-09 | 审计留痕 | 任务执行完毕 | 每条写操作记录含时间、主体、对象、结果、`request_id` |
| AC-10 | 预演模式 | `dry_run=true` | 无写接口调用，输出预期动作清单 |
| AC-11 | 幂等验证 | 对同一用户重复执行迁移 | 不产生重复成员关系，状态记为幂等成功 |
| AC-12 | 分页完整性 | 用户所属组超过 100 个 | 翻页取全，正确匹配旧组 |

### 13.3 回退方案

若迁移后发现业务受影响，回退方式为反向操作：将用户重新加入旧用户组（`CreateGroupMembership`），并从新用户组解绑（`ListGroupMembershipsForMember` + `DeleteGroupMembership`），与本期实现复用同一组接口。回退须基于执行记录中的 `membership_id` 与 `user_id` 精确定位对象，并由安全侧审批后执行。

### 14.1 接口调用顺序示意

| 序号 | 功能一（退出旧组） | 功能二（加入新组） |
|------|--------------------|--------------------|
| 1 | `ListGroupMembershipsForMember`（翻页取全） | `ListGroups`（按显示名匹配，取 `group_id`） |
